# v0.8.0 — the home repo

## What changed

- **No Deceit is a git checkout you keep, not a package.** The checkout is a
  *home* with four gitignored personal dirs: `projects/` (governed projects),
  `data/` (curricula, refs, evidence, verdicts, the project manifest — its own
  nested private git repo), `state/` (ledger, sessions), `config/`.
- `nd bootstrap [--dry-run] [--claude] [--opencode] [--pi] [--cursor]` creates
  the layout and links the checkout into each harness (Claude Code: a symlinked
  skills-dir plugin at `harness/claude-code`; OpenCode and Pi: a symlink; Cursor:
  a `preToolUse` entry merged into `~/.cursor/hooks.json`). If it finds an
  existing marketplace install, an older `~/.claude/skills/no-deceit`, an
  OpenCode or Pi link already pointing elsewhere, or a `~/.cursor/hooks.json`
  that is not valid JSON, it stops with nothing changed and prints the step to
  fix it (`claude plugin uninstall no-deceit`, or move the old entry aside), so
  the hooks never fire twice; re-run it afterwards. It never overwrites a link
  or file it did not create and never edits your shell profile.
- `nd project add <git-url|path>` clones (or adopts, in place) a project,
  registers it in the data home's project manifest (the existing
  `projects.edn`/`projects.json`, else `data/projects.edn`) and opts it in at
  Tier 2.
- `nd update` fetches, fast-forwards only, never touches `projects/ data/
  state/ config/`, and prints the release notes between your old and new HEAD,
  plus `reread:` and `rebootstrap:` flags.
- With a home, state and config resolve to `<home>/state` and `<home>/config`
  (`ND_HOME`, auto-detected from the `.nd-home` marker bootstrap writes);
  without one, the XDG paths still work exactly as before. Bootstrap copies an
  older XDG ledger, `config.json` and data tree into the home once (recorded in
  `state/`, so a re-run never brings back a file you deleted), leaves the
  originals, and never overwrites a file the home already has.
- `adapters/` is now `harness/` (one folder per harness, shared mapping and
  tests beside them). The root `.claude-plugin/` marketplace manifest,
  `package.json`'s `pi` key and `.cursor-plugin/plugin.json` were repointed so
  existing marketplace, Pi and Cursor installs keep working. `package.json` is
  now private with no `main`, `files` or `bin`: **npm publishing is over**.
- `nd --cursor` stays as Cursor's transport for one more release.
- `docs/releases/` (this shape) and `docs/decisions/` (D1–D8, R1–R8, including
  the D6 and default-tier reversals and R8 as the captain decided it).
- README rewritten for the home-repo install.

## Why

The learning material — curricula you wrote by hand, the evidence you
produced, the ledger that keeps you honest — is the valuable part and must never
land in a shareable tree, yet must be versioned and backed up (R7). A
firstmate-style home gives that a place, makes `git pull` the whole update story
(the symlinked plugin updates in place; no reinstall), and finishes the
packaging *before* the language changes, so the incremental Babashka port
(R8, done by the captain) is invisible to users. See
`docs/decisions/r1-r8.md`.

The root marketplace `source` deliberately stays `./` (not
`./harness/claude-code` as the redesign report sketched): a marketplace install
caches only the `source` directory, which would cut the plugin off from `core/`.

## What you should notice

- New commands: `nd bootstrap`, `nd project add`, `nd update`; `nd doctor` now
  prints a `home:` line. All three are refused from an agent shell and
  classified as tamper (category G) like the other state-changing `nd` commands.
- After `git pull` / `nd update`, restart your harness when `reread: yes` (it
  also covers `hooks.json` and `core/` / `harness/` changes, which running
  sessions load once).
- If `nd bootstrap` says a marketplace install exists, or that a harness link
  already points somewhere else, it stops for every harness and tells you what
  to remove; it will not choose for you. It does not look inside Pi's,
  OpenCode's or Cursor's package stores: remove a package install first (the
  exact commands are in README's install section).
- **Not live-verified:** that Claude Code loads a *symlinked* skills-dir plugin's
  hooks, that OpenCode resolves its plugin's relative import through a symlink,
  and that Cursor accepts the merged absolute-path hook. What was checked
  offline, and the fallback for each, is in `docs/verification/<harness>.md`.
- Audit gate for this release: no grader prompt or rubric changed
  (`nd audit --oracle`: `graded_up: 0`).

## Captain steps (outward-facing; a worker did not run any of these)

### 1. Deprecate the npm package

`docs/releases/npm-0.7.2/` is a self-contained tombstone release: a
`package.json` (`no-deceit@0.7.2`, `files` = `README.md` + `postinstall.js`,
no dependencies, no `bin`), a `postinstall.js` that only prints the move
notice, and a README. Publish it **from that directory** (the repo root
`package.json` is private and cannot be published), then deprecate. Do not
unpublish — it breaks lockfiles.

```bash
cd docs/releases/npm-0.7.2
npm pack --dry-run          # must list exactly: README.md, package.json, postinstall.js
npm view no-deceit version  # expect 0.7.1 (so 0.7.2 is next)
npm login                   # once, interactively
npm publish
npm deprecate 'no-deceit@<=0.7.2' 'moved to https://github.com/PDepaula/no-deceit (git install); npm package unmaintained'
npm view no-deceit@0.7.2 deprecated   # confirm the message shows
```

If `npm publish` asks for a one-time password, pass `--otp <code>`.

### 2. Tag and publish the GitHub release (after the PR merges)

```bash
git tag v0.8.0 && git push origin v0.8.0
gh-axi release create v0.8.0 --title 'v0.8.0 — the home repo' --notes-file docs/releases/v0.8.0.md
```

### 3. Move your own install

```bash
claude plugin uninstall no-deceit    # only if it came from the marketplace
mv ~/.claude/skills/no-deceit ~/no-deceit.old   # the old clone; out of the scanned skills dir
git clone https://github.com/PDepaula/no-deceit ~/no-deceit && cd ~/no-deceit && bin/nd bootstrap
```
