# R1–R8: the redesign calls

No Deceit is being redesigned from a code-only gate into a principle-transfer
learning framework. The captain approved the redesign report's recommendations
("all recommended … except for number 8"), with one change to R8. Phases 1–2
landed the tier default, handover, diagram gate, evidence capture and the
transfer grader; phase 4 (this) landed the home repo.

<a id="r1"></a>
## R1 — Tier 2 is the default for every governed project

One default is easier to reason about; `nd tier 1` is one command away for
code, and the ledger will show whether it is used. **Reverses** the Tier 1
default implicit in [D1](d1-d8.md). Projects initialised earlier keep their
stored tier. *Code:* `DEFAULTS.tier` in `core/state.mjs`, `nd init`.

<a id="r2"></a>
## R2 — Tier 1 requires a curriculum artifact to exist

Existence, not captain review: a cheap deterministic check like the Tier 3
preamble. `nd status` will nag on unreviewed curricula. *Code:* phase 3.

<a id="r3"></a>
## R3 — Transfer pass rule: P1 ∧ P2 ∧ P4 ∧ (P3 ∨ P5)

P2 (a real project, from the manifest) and P4 (a falsifiable judgment) are the
two that separate transfer from recall and judgment from endorsement. Requiring
P5 too fails honest first teach-backs; "any three" lets recall plus benefit
pass. *Code:* `core/rubric.mjs`.

<a id="r4"></a>
## R4 — Diagram file writes stay denied even at Tier 2 unlocked

Diagrams go in chat only and the learner redraws them, the same rule as worked
code ("you type it"). The artifact passing through the learner's hands is the
point. *Code:* category H in `core/classify.mjs` / `core/policy.mjs`.

<a id="r5"></a>
## R5 — Parse Excalidraw now; rendering and vision behind a flag later

Parsing is deterministic and gold-settable. Rendering answers a real criterion
but adds a dependency and a data-sharing choice; the renderer is chosen when
phase 6 starts. The parsers are written by the captain in Babashka
(`PORTING.md` step 7).

<a id="r6"></a>
## R6 — No live LLM leak judge; offline audit only

Keeps the standing rule, keeps parity across harnesses, keeps the gate fast and
fail-closed. Revisit only if the offline audit shows unlabelled handovers are
common.

<a id="r7"></a>
## R7 — `data/` is its own nested private git repo

Curricula and evidence are the most valuable files in the system and the only
ones written by hand; losing them would be the real deceit. A nested repo with
an optional private remote versions them without ever entering the shareable
tree (a private fork of the whole home would make sharing the home harder).
*Code:* `nd bootstrap` `git init`s `data/`; `/data/` is gitignored in the home.

<a id="r8"></a>
## R8 — The Babashka port is incremental, by the captain, woven into the testing phases

**Decided differently from the report's recommendation.** The report proposed
"port last" (option a). The captain instead chose to *dogfood* the idea and
port incrementally from the current Node version because he wants to learn
Clojure: he writes each Babashka namespace himself, in the phases that involve
testing, "even before all the features are baked out". Agents build only the
scaffolding, oracle cases and fixtures (`oracle/`, `bb.edn`, `test/`,
`PORTING.md`); no agent writes `src/` Clojure. The Node suite stays the source
of truth until a namespace is cut over. `bb` is installed by mise
(`mise.toml`), not by `nd bootstrap`.

## Packaging note (phase 4)

The report proposed repointing the root marketplace `source` to
`./harness/claude-code`. It is kept at `./` instead: a marketplace install
caches only the `source` directory, and the skills-dir plugin under
`harness/claude-code` forwards to `hooks/` and reads `skills/` and `agents/` by
symlink into the repo root, which a cache copy of that folder alone would lack.
Existing marketplace users therefore keep working unchanged. See
`docs/verification/claude-code.md`.
